# Git view implementation inventory

This task snapshot is the working contract for the opt-in Git layout. The first implementation slice keeps existing actions on their existing components and handlers; it does not claim the full redesign is complete.

The picker currently shares the legacy branch-history component/data path. Favorites and recent refs persist in browser storage scoped by profile/workspace/root. Selected History ref, commit search, and graph query settings (remote refs, author, date range, paths, sort, limit, compare base, and graph/list mode) are kept by the Git UI store scoped by profile/workspace/root. Graph, branch, tag, compare, commit diff, and working diff results have request/context guards; post-action preview refreshes capture their originating root/path/scope and cannot replace another root's selection. Tag-list failures render an inline alert. Compact History keeps commit text search by message, author, or hash and reports no-match state. `HEAD` and all-refs are distinct graph queries. Saved refs remain visible during loading, deleted refs are explained, and missing refs are pruned after completed reads; loading/error transitions are guarded. Table entries describe implemented transport and scope behavior; human confirmation of actual view presentation remains pending.

The narrow Changes diff also provides the layer label, stage/unstage file and hunk actions, and Commit staged. These controls use the same store APIs as desktop Changes.

The shared Git toolbar includes a keyboard-focusable native Details disclosure for the complete active repository path and working branch. The compact branch chip remains unchanged; long paths wrap inside the disclosure panel.
